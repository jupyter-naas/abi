# `ontologies/` — AGENTS.md

> Scope: ontology definitions for the `{{module_name_snake}}` module. See the module's [AGENTS.md](../AGENTS.md) for module-wide context.

## Layout

```
ontologies/
├── modules/     {{module_name_pascal}}Ontology.ttl        shared classes + owl:imports of each process
├── processes/   {{module_name_pascal}}Process.ttl         one BFO process slice per file
├── queries/     {{module_name_pascal}}SparqlQueries.ttl   templatable SPARQL → agent tools
└── classes/     generated by onto2py — do NOT hand-edit
```

`BaseModule.on_load()` globs `ontologies/**/*.ttl` **recursively**.

**`modules/`** — shared classes (used by more than one process, or by SPARQL/pipelines independently of a process). Import `abi:Ontology` rather than redeclaring `Person`, `Organization` or `Site`. The module `owl:imports` every process IRI.

**`processes/`** — slices. A process file may define only its process class, process-only properties, and restrictions on shared IRIs. Reuse module IRIs; do not mint new shared classes here. Import `abi:Ontology` plus the CCO mid-level you need — **do not** import the module ontology (that would cycle).

**`queries/`** — `intentMapping:TemplatableSparqlQuery` individuals. `intentDescription` is the question a user would actually ask.

**`classes/`** — generated action-class stubs. Commit them; never edit them.

## Restrictions (seven buckets)

Use **`abi:` properties**, not raw `bfo:`, so inverses from ABIOntology carry over (`abi:hasParticipant`, `abi:concretizes`, `abi:realizes`, `abi:inheresIn`, `abi:occursIn`, `abi:occupiesTemporalRegion`).

Every process class gets the full set unless a bucket is omitted with a TTL comment:

| Bucket | Question | Restriction |
|---|---|---|
| WHAT | what is happening | subclass `abi:Process` (or a CCO process) |
| WHEN | over what interval | `occupiesTemporalRegion` → `abi:TemporalRegion` |
| WHO | which participant | `hasParticipant` → Person and/or quality |
| WHERE | at what place | `occursIn` → `abi:Site` |
| HOW WE KNOW | which record | `concretizes` → GDC |
| HOW IT IS | which quality | quality `inheresIn` a bearer; may `hasParticipant` the process |
| WHY | which role or disposition | `realizes` → Role ∪ Disposition |

A vacant requisition is a GDC, not a role: a BFO role must inhere in a bearer.

**CCO first.** Do not mint a class when CCO has one. Keep a module-local name with `owl:equivalentClass` / `rdfs:subClassOf` the CCO IRI so pipelines keep stable Python names.

## Conventions

- **Stable IRIs** under `http://ontology.naas.ai/{{module_name_snake}}/`.
- **One `owl:imports` statement per IRI.** A comma-separated continuation is silently dropped by onto2py's codegen pre-scan.
- **Locator annotations** on every ontology header — `abi:pythonPackage`, `abi:ontologyResource`, `abi:pythonResource`.
- **Pair every relation with its inverse**, and subclass an `abi:` relation.
- **Schema only.** Named individuals belong in pipeline output. Anything in a TTL here lands in the live triple store.

## Regenerating

Process files that restrict shared IRIs undeclared in that file fail the standalone checker. Generate processes first with the skip, then the module (the module run validates the combined graph):

```bash
ABI_SKIP_ONTOLOGY_CHECK=1 uv run python -m naas_abi_core.utils.onto2py \
  {{module_name_snake}}/ontologies/processes/{{module_name_pascal}}Process.ttl
uv run python -m naas_abi_core.utils.onto2py \
  {{module_name_snake}}/ontologies/modules/{{module_name_pascal}}Ontology.ttl
uvx ruff check --fix {{module_name_snake}}/ontologies && uvx ruff format {{module_name_snake}}/ontologies
```

A `could not resolve owl:imports` warning for CCO mid-level / BFO is expected: those files have no locator annotations. The TTL still loads into the triple store in full.

Import models from `ontologies/modules/` or `ontologies/processes/`. Import from `ontologies/classes/` only for an action-class stub you have extended.
