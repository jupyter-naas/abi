# Maps graph layers

Modules register `GraphMapLayer` descriptors in their FastAPI hook with `register_map_layer`. ABI contains the reusable catalog and viewer; company-specific evidence and projection queries stay in their module.

`service.py` defines the read-only `GraphQueryPort`, descriptor and catalog. The primary adapter exposes `GET /api/maps/layers` and `GET /api/maps/layers/{id}`. Both are IAM's (`ListLayers`, `GetLayer`), resolve existing graph grants and disable caching. Projections receive `WorkspaceGraphStore`, never the unrestricted catalog store. The declared graph must be readable before the feed runs. Snapshot selection belongs to the module; never union historical snapshots automatically.

Each pin can carry `entityUri`, `graphUri`, `country`, `precision`, `observedAt`, `sources`, `relationships`, `address`, `photoUrl`, `streetViewUrl` and `imageSearchUrl` for the inspector. The inspector embeds a cited photo or a same-origin `/api/maps/streetview` preview from lat/lng. Treat pin labels and sources as untrusted content. Only HTTP(S) evidence links are navigable; KG links are constructed within the current workspace.

Optional `coverage: {pins: [...]}` provides city summaries from the same scoped projection. Each city pin has its own graph identity, coordinates and evidence, with `memberIds` linking address pins. The browser renders geographic country fills, never materializes countrywide operations as RDF facts, and validates member IDs against the returned address pins.

# Maps catalog (layers, basemaps, access)

ADRs: `docs/adr/20261012_nexus-maps-catalog-and-access.md`, `docs/adr/20261013_nexus-maps-groups.md`.

- `layouts/` — **feeds** (data sources): `group` (sidebar group label: feeds sharing it form one group; no group records) and `feed_type` `sparql` (query on the workspace graphs), `object_storage` (each layer reads a GeoJSON object, see `manifests.py`) or `geojson_url` (a `/api/...` path the web proxy `/api/maps/custom/{feed}` calls with the member's token). Module data belongs in manifests (`object_storage`); a `geojson_url` target must authenticate the member itself. Never serve feed data unauthenticated. `/api/maps/feeds` (= `/api/maps/layouts`: CRUD, `/visibility`, `/color`, `GET /{id}`). Deleting a feed goes through `feed_layers` (cascade).
- `feed_layers/` — **layers**: views on one feed (title, color, icon, order, `class_labels` = feature types kept, empty = all; `storage_path` = the layer's GeoJSON object for `object_storage` feeds). `/api/maps/feed-layers`; `GET /{id}/data` serves a stored layer (member, layer and feed visible; `?all=true` skips its types; missing object → 503). Seeded layers keep their `storage_path`, and a new layer on a stored feed takes the feed's object. A feed always keeps one layer; new feeds get a default layer with the feed id. Hidden flags share `hidden_layouts`.
- `basemaps/` — basemap records with a renderer config (`tile`, `countries` + palette, `geojson`; vector kinds may declare `regions`: labelled groups of countries the map counts pins by) and preview bytes. `/api/maps/basemaps` (CRUD, `/visibility`, `GET|PUT /{id}/preview`). Core seeds and their previews: `basemaps/builtin.py`, `basemaps/assets/`.
- `settings/` — per-workspace JSON in `maps_settings`: hidden layers/basemaps, `hidden_feeds` (whole feeds switched off: `PUT /api/maps/layouts/{id}/feed-visibility`, or several at once with `POST /api/maps/layouts/feed-visibility`; built-in and graph layers are one-layer feeds with the same id), colors of record-less layers, applied seeds. Always read-modify-write the whole document through the port.
- `manifests.py` — modules declare feeds, layers and basemaps like apps: `<module_root>/artifacts/maps/layers/**/manifest.json` (any folder depth, e.g. `layers/facilities/<org>/`; the feed is its slug, not its folder; slug, name, version, group, icon, color, `logo_path`, basemap, `layers[]` with `storage_path` and `class_labels`) and `artifacts/maps/basemaps/<id>/manifest.json` (slug, name, version, category, order, renderer, preview file). Metadata only: data and logos are object storage keys (`storage_keys.py`), read through `objects.py` (port) / `adapters/secondary/object_storage.py`. Registered at API startup as seeds with `revision=version`; a broken manifest or duplicate slug is logged and skipped. Feed logos: `GET /api/maps/layouts/{id}/logo`. ADR `20261013_nexus-maps-module-manifests.md`.
- `seeds.py` — `register_maps_seeds(app, layouts=..., feed_layers=..., basemaps=...)`, the backend of the manifests (a module may still call it from its API hook). Seeds are copied once per workspace and become `system` (edit/hide, never delete; their data source — feed type, `logo_path`, layer `storage_path` — stays the seed's). Bump `revision=` to migrate seeded copies (feeds, layers, basemaps) in every workspace (`settings.seed_revisions`).
- `workspace_config.py` — a workspace's initial Maps setup from `config.*.yaml` (`workspaces[].maps`: `feeds: [...]`, `basemaps: {custom: [...]}`; ADR `20261013_nexus-maps-workspace-config.md`). Each feed and custom basemap is decided once per workspace (`seed_revisions["feed-init:<id>"]` / `["basemap-init:<id>"]`): enabled when listed, else disabled; Settings → Maps wins afterwards. Built-in basemaps are always enabled; feeds and basemaps an admin creates start enabled. Every enabled feed is on when the map opens. `adapters/primary/workspace_defaults.py` resolves the block by workspace slug for the catalog and list routes, and logs config ids no module provides at startup.
- Hot read paths (`/feed-layers/{id}/data`, `/layouts/{id}/logo`): a map opening fires many requests at once. They sign in with `get_current_user_released` (own short session: a request-scoped session holds a pooled connection while waiting, and the pool runs dry), decide the access in the route with IAM at every request (`authz.require`, in process: never cached), and keep what a layer resolves to (30 s) and the objects (60 s) in the engine cache's hot tier through `cache.py` (`MapsCache`: Redis, failures are misses, concurrent misses share one load). `?all=true` sends the stored object as is. The web shares one load per object (`shared-feed-loads.ts`) between the map, sidebar counts and Settings.
- `permissions/` — `maps_grants`: deployment items everywhere unless narrowed; custom items at home unless shared (read-only, `shared_from`). Deployment items and "all workspaces" need a platform administrator (IAM's `builtin.platform_admin`). Services enforce it on list/get/preview; `/api/maps/permissions` manages it.
- `catalog/` — `GET /api/maps/catalog`, the single read the web store loads.

Run `pytest` on this directory (service and colocated API tests). Frontend contract tests live beside `maps/lib/maps-feed.ts`, `maps-basemaps.ts`, `maps-country-cluster.ts` and `permissions-api.ts`.

## Authorization

Every route authorizes with an IAM action of the `nexus` catalog (`iam/catalog/knowledge.py`): feeds are the `layout` type (`ListLayouts`, `GetLayout`, `UpdateLayout`, `DeleteLayout`, `SetLayoutVisibility`, `PreviewLayout`), a feed's layers `feed_layer` (`ListFeedLayers`, `GetFeedLayer`, `UpdateFeedLayer`, `DeleteFeedLayer`), `basemap` (`ListBasemaps`, `GetBasemap`, `UpdateBasemap`, `DeleteBasemap`, `SetBasemapVisibility`), the catalog read `GetMapsCatalog` and `maps_access` (`GetMapsAccess`, `UpdateMapsAccess`). Viewers read, admins author; `can_edit` in a read is `authz.allowed("UpdateLayout" ...)`. Never check a role. The workspaces a user may grant to (`permissions/adapters/secondary/postgres.py`) are the ones IAM lets them `UpdateWorkspace`; a platform administrator is `is_platform_admin`. Tests act as a user of `graph/testing.knowledge_team` (`acting_as_header`).
