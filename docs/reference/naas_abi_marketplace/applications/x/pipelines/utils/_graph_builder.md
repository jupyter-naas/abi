# XTweetGraphBuilder

## What it is
- A shared helper for mapping X (Twitter) v2 `Tweet`-shaped dictionaries into RDF triples.
- Designed to produce an identical RDF graph shape whether tweet records come directly from the X v2 API or from replayed persisted JSON envelopes.
- Performs lightweight de-duplication against an existing named graph via SPARQL `ASK`, with an in-process cache to avoid repeated checks.

## Public API
### Class: `XTweetGraphBuilder`
Instantiate once per run with a triple store and named graph.

- `__init__(triple_store: ITripleStoreService, graph_name: URIRef | str, ontology_namespace: str | None = None)`
  - Stores triple store handle and named graph.
  - Uses `ontology_namespace` if provided; otherwise reads `ABIModule.get_instance().configuration.ontology_namespace`.
  - Initializes an internal `(class_uri, label) -> bool` existence cache.

- `uri(class_name: str, stable_id: str) -> str`
  - Returns a deterministic instance IRI using `uri_for(namespace, class_name, stable_id)`.

- `prop(local_name: str) -> URIRef`
  - Builds a raw property IRI as `URIRef(f"{ontology_namespace}{local_name}")`.
  - Used for properties that cross ontology-module boundaries and may not be generated by onto2py.

- `label_exists(label: str, class_uri: str) -> bool`
  - Checks whether an instance of `class_uri` with `rdfs:label == label` already exists in the configured named graph.
  - Runs a SPARQL `ASK` against `GRAPH <graph_name>`.
  - Memoizes results for the lifetime of the builder.
  - On query failure, logs a warning and returns `False` (assumes absent).

- `mark_existing(class_uri: str, label: str) -> None`
  - Marks `(class_uri, label)` as present in the in-process cache (used after emitting new individuals).

- `build_user(record: dict) -> tuple[XUser, Graph]`
  - Delegates to `naas_abi_marketplace.applications.x.pipelines.utils.build_user.build_user(self, record)`.

- `build_media(record: dict) -> tuple[Media, Graph]`
  - Delegates to `naas_abi_marketplace.applications.x.pipelines.utils.build_media.build_media(self, record)`.

- `build_tweet(record: dict, source_set_uri: str | None = None, *, referenced: bool = False) -> Graph`
  - Delegates to `naas_abi_marketplace.applications.x.pipelines.utils.build_tweet.build_tweet(self, record, source_set_uri, referenced=referenced)`.

### Re-exported helpers
These are re-exported from `...pipelines.utils._helpers` for backward-compatible imports:
- `first`
- `parse_dt`
- `uri_for`

## Configuration/Dependencies
- Requires an implementation of `ITripleStoreService` with a `.query(sparql)` method returning an object with `.askAnswer`.
- Uses:
  - `rdflib` (`Graph`, `URIRef`, and `rdflib.namespace.RDFS`)
  - Ontology classes from `naas_abi_marketplace.applications.x.ontologies.modules.XOntology` (e.g., `Tweet`, `XUser`, `TweetURL`, etc.)
  - `ABIModule.get_instance().configuration.ontology_namespace` when `ontology_namespace` is not provided.
- Named graph is treated as a string IRI (`graph_name` is stored as `str(graph_name)`).

## Usage
```python
from rdflib import URIRef
from naas_abi_marketplace.applications.x.pipelines.utils._graph_builder import XTweetGraphBuilder

# triple_store must implement ITripleStoreService
builder = XTweetGraphBuilder(
    triple_store=triple_store,
    graph_name=URIRef("urn:graph:x"),
)

tweet_record = {"id": "123", "text": "hello"}  # tweet-shaped dict as expected by build_tweet
g = builder.build_tweet(tweet_record, source_set_uri="urn:resultset:abc")

# g is an rdflib.Graph containing generated triples for this tweet record
print(len(g))
```

## Caveats
- De-duplication is based on `(rdf:type == class_uri) AND (rdfs:label == label)` in the configured named graph; it does not check other properties for equality.
- If the triple store query fails (any exception), `label_exists` assumes the label is absent and may re-emit individuals/triples.
